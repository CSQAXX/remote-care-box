### 1.3 环境注意事项（踩过的坑，别再踩）

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| **系统代理拦截 git** | `schannel: failed to receive handshake` / `unexpected eof while reading` | **执行 git 前先清空 `HTTP_PROXY` / `HTTPS_PROXY`**。已实测：清空后 git 访问 GitHub 正常，走代理反而失败 |
| 端口 COM3 被占 | `Port COM3 in use` | 关掉其他串口监视器（Arduino IDE / 串口助手 / 上一次的 monitor） |
| flash 配置不符 | `Flash size mismatch` | sdkconfig 的 `FLASHSIZE_16MB` 必须开 |
| PSRAM 配错 | `Camera init failed with error 0x105` | `SPIRAM_MODE_OCT` / `SPIRAM_SPEED_80M` / `SPIRAM_USE_MALLOC` 三项缺一不可 |
| ESP32-S3 只支持 2.4G | 连不上 5G 网络 | 路由器开 2.4G 兼容模式；备一个手机热点 |

### 2.3 如果例程不带推流（自己写的兜底骨架）

ESP-IDF 官方有现成的 HTTP server + camera 例程，逻辑很简单：

```c
// 思路骨架，不是最终代码
static void http_get_stream(httpd_req_t *req) {
    // 设置 multipart 头
    // 循环：esp_camera_fb_get() -> 写 frame->buf -> esp_camera_fb_return()
    // 每帧前写 boundary 头
}
```

**关键点**：
- 必须用 `esp_camera_fb_get()` 而不是 `esp_camera_fb_get2()`（后者零拷贝但要求 PSRAM 常驻，调试期容易踩坑）
- `Content-Type: multipart/x-mixed-replace; boundary=frame`
- 循环里要 `vTaskDelay` 或按帧率让出 CPU，否则看门狗会咬人
- 只能有**一个**客户端同时连（ESP32-S3 内存吃紧），网页刷新一次只开一个请求

## 3. 阶段三：M2 按键弹话

### 3.1 任务分解

| # | 任务 | 说明 | 必做/选做 |
| --- | --- | --- | --- |
| 1 | 拆壳确认按键 GPIO | 用万用表短接 GPIO 到 GND 看串口日志；或查正点原子原理图 | 必做 |
| 2 | 固件加 `btn_task` | 短按触发（松开才触发，防长按重复），写一条事件到队列 | 必做 |
| 3 | 固件开 `GET /event` | 无事件返回 `{"type":"none"}`，有事件返回内容并清除 | 必做 |
| 4 | 网页轮询 + 弹提示 | 每 500ms 拉一次 `/event`，有事件就 `alert(msg)` | 必做 |
| 5 | 文案可配置 | 提取成一行宏/常量，改完重烧即生效 | 必做 |
| 6 | 板子主动 TCP 推送 | 板子当客户端连电脑 `:5555`，电脑 Python 脚本收 | 选做 |
| 7 | 板载 LCD + 蜂鸣 | 收到事件时 LCD 显示 + 响一声 | 选做 |

### 3.2 关键技术点

**GPIO 按键怎么读**：
- 上拉输入（`GPIO_MODE_INPUT` + `GPIO_PULLUP`），按下 = 低电平
- **消抖**：硬件消抖 20ms 即可，别写复杂的
- **边沿触发**：用 `gpio_isr_handler_add` 挂中断，或简单点用 20ms 轮询检测状态跳变
- 短按 = 松开时触发（`pressed == true` 后等 `released` 才上报）

**事件队列**：
- FreeRTOS 队列，长度 8 足够
- 出队时机：只有 `/event` 被访问时才出队（这样"没人看网页"时事件会堆积？→ 队列满了就丢最旧的，或者干脆出队时判断时间戳，1 分钟前的直接丢）

**降级方案（必须保留）**：
如果 TCP 推送做不通，网页轮询 `GET /event` 已经完全能实现 A5 验收标准。**不要为了做推送卡住整个 M2。**
